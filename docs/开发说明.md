# 开发说明

当前已有登录、退出、修改密码和账号管理；仓库业务页面仍为占位页。

## 本地启动

要求 Node.js 22、npm 与 Docker Desktop（或已有 PostgreSQL 实例）。在项目根目录执行：

```powershell
npm install
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

将 `.env` 中的 `AUTH_SECRET` 改为随机密钥（至少 32 个字符）。可用 `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"` 生成。`.env` 仅用于本机，不能提交到仓库。然后继续：

```powershell
docker compose up -d db
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

第一次执行 `npm run db:seed` 会创建用户名 `admin` 的超级管理员，并在终端**仅显示一次**随机初始密码。请记录该密码，登录 `http://localhost:3000/login` 后立即在“修改密码”页面更换。若希望指定初始密码，可在第一次播种前设置 `ADMIN_INITIAL_PASSWORD` 环境变量，密码至少 12 个字符且不超过 72 字节。重复执行播种命令不会重置现有管理员密码。

管理员可在“用户与权限”页面创建业务员账号及重置业务员密码。业务员不能访问该页面。所有已登录用户都可以修改自己的密码，修改后会退出登录，旧会话同时失效。系统没有公开注册入口。

若已经有 PostgreSQL 服务，可将 `.env` 中的 `DATABASE_URL` 改为该数据库的连接地址，无需启动 Compose。
本项目的 Docker 数据库映射到本机 `5433` 端口，避免与其他使用 `5432` 的 PostgreSQL 冲突。

## 代码结构

- `src/app`：App Router 页面、认证回调与服务端表单操作。
- `src/auth.ts`：Auth.js 凭据登录和会话配置。
- `src/features/identity`：密码规则和哈希处理。
- `src/server`：Prisma 客户端与服务端身份检查。
- `src/config/navigation.ts`：计划中的页面入口。
- `prisma`：用户模型、迁移和 `admin` 初始化脚本。

业务模块后续仍按方案实现。库存写入应集中在服务端事务中；页面组件不直接计算或修改库存余额。
