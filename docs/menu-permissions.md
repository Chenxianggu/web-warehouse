# 用户菜单权限

超级管理员在“菜单管理”中选择配置对象，系统自动加载对应权限，勾选菜单后保存。切换期间禁止编辑和保存，避免将权限写入前一个配置对象。底部会标明当前保存对象。也可从“用户管理”里的“菜单权限”入口直接编辑该用户。

- 默认权限适用于所有未单独配置的业务员，新账号自动继承。
- 为指定业务员保存后，该用户使用独立的完整菜单白名单，之后修改默认权限不会影响他。可以开放默认关闭的菜单，也可以全部关闭。
- “恢复默认权限”删除个人配置，使该用户重新跟随当前默认规则。
- 首页、修改密码始终开放；用户管理、菜单管理始终仅超级管理员可用。超级管理员始终拥有全部权限。
- 侧栏、首页入口、业务页面、服务端操作与导出统一使用当前用户的有效权限。保存后，下一次请求会读取新配置；已打开的页面不会主动刷新，已加载内容仍可能显示，但后续服务端请求会重新校验。
- 新增业务菜单对跟随默认的用户延续现有默认开放规则；使用个人白名单的用户需要显式授权。

个人配置保存在 `user_menu_permissions`，无记录表示继承，空数组表示关闭全部业务菜单。配置变更与审计日志在同一事务中提交，删除账号会级联清除配置。

部署前执行 `npm run db:generate` 与 `npm run db:migrate`。本功能迁移为 `20261016000000_add_user_menu_permissions`，不修改现有默认权限。

验证：`npm run test:menu-permissions`；设置 `RUN_DATABASE_TESTS=1` 后运行 `npm run test:menu-permissions:db` 可验证数据库隔离、恢复默认、审计与级联清理。
