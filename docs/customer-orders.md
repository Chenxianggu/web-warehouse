# 客户订单

入口：`/customer-orders`。行为对照参考项目的 `frontend/src/views/Orders.vue` 与 `backend/server.js` 中订单接口实现。

- 默认显示上海时区当天订单；选择日期后筛选，清空日期后显示全部订单。
- 未出库订单点击后加载到编辑表单，可更新、删除或切换到新建；已出库订单只能打开详情，服务端同样禁止修改和删除。
- 客户与塑料编号支持编号、中文、全拼、首字母搜索；选择后带出名称，仍允许手填编号和名称。
- 收货单位按客户读取历史，允许新增输入；“自提”复选框与收货单位文本双向同步。保存时自动去重记忆收货单位。
- “是否扣寄仓数量”保存为订单标记。与参考项目一致，保存订单本身不扣库存或寄仓，扣减由发货流程处理。
- 明细支持多行、删除、备注；至少一行，编号/名称/正整数包数必填，单价非负、两位小数，可不填（保存为零）。
- 订单号为订单日期 `YYYYMMDD` 加至少三位流水号；编辑日期保留原订单号。按日期加事务锁分配流水，支持同日并发创建及超过 999 笔。
- 只读详情金额为 `单价 ÷ 每吨包数 × 包数`；每吨包数取当前塑料资料，找不到时为 40，与参考接口一致。

订单不依赖客户、塑料主档的外键，以保留手填数据和历史快照。收货历史也允许未建档客户，因此移除了其客户外键；客户资料更新编号和删除时，由原有操作的事务维护收货历史。

## 数据库与验证

运行 `npm run db:generate`、`npm run db:migrate` 应用模型与迁移。

- `npm run test:orders`：日期、必填、数量、价格、备注与金额计算测试。
- PowerShell 下先设置 `$env:RUN_DATABASE_TESTS='1'`，再运行 `npm run test:orders:db`：验证真实数据库的并发编号、创建、更新、收货历史、日期筛选、已出库保护、级联删除和四位流水号。该测试使用独立标识的临时数据并自动清理。
- `npm run typecheck`、`npm run lint`、`npm run build`：静态检查与生产构建。
