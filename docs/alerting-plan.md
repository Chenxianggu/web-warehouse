# 手机报警实施计划

## 目标与范围

复用 Alloy → Loki → Grafana，将生产异常发送到手机；第一版使用确定性规则，不接入 AI。AI 原因分析作为后续可选功能，不阻塞报警。日志报警独立于业务进程与业务数据库；整机故障由另一台机器上的存活监测器发现。

## 实施步骤

1. 补齐关键业务事务的失败埋点，排除普通校验/约束冲突，沿用日志脱敏；关联编号同时用于数据库审计和异常排查。
2. 提供不缓存的 `/api/health`，实际检查数据库连接，失败返回 503，不公开内部错误。
3. 预置 Grafana 生产规则：数据库不可用、日志落库失败、5 分钟请求异常 ≥ 5 次、业务写入异常 ≥ 3 次、数据库错误 ≥ 3 次、登录失败 ≥ 10 次；每 30 秒评估。
4. 独立通知服务接收经过认证的 Grafana Webhook，将通知先写入持久队列，再异步发送；支持钉钉签名、失败退避重试、重复抑制和恢复通知。密钥只从文件读取，不进 Git 和日志。
5. 外部存活监测器每 30 秒检查公开 HTTPS 健康接口，连续 3 次失败报警、连续 2 次成功通知恢复，持续故障每 30 分钟提醒。状态及通知队列持久化，必须部署到另一台机器。
6. 增加自动测试和 CI：覆盖签名、平台错误码、失败重试及重启恢复、鉴权、去重、故障/恢复、敏感信息保护；提供隔离的 Grafana → 接收服务集成验证和手机试发命令。
7. 更新部署、密钥配置、报警阈值调整与验收手册。

## 验收标准

- 普通校验失败不推送；模拟异常满足阈值后报警，窗口内无新增异常后发送恢复通知。
- 同一报警不会短时间刷屏；手机渠道失败不影响业务请求，未发送通知在服务重启后继续重试。
- 外部监测器在业务服务器停机后仍能通知；正常恢复只发一次恢复通知。
- 仓库与 CI 不需要真实手机凭据，集成测试只向本机模拟接收端发送。
- 日志报警生产上线须有渠道密钥和生产连接；整机存活报警另需独立监测主机。钉钉接口接收成功与手机实际到达分别确认，不能以本地模拟替代。

## 默认决策及限制

用户已选择钉钉；完成本地验证后，于 2026-10-20 授权部署生产并模拟报警。现阶段只有一台业务服务器，先上线日志报警，外部存活监测器暂不部署。不自动开放 Grafana 公网端口。不自动修复或更改业务数据。机器人通知受手机通知权限和免打扰影响。持久队列提供至少一次投递：平台已接收但本地尚未记录时进程崩溃，可能重复一条。容器集成验证需要可用 Docker；其余测试可独立运行。
